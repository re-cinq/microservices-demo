# Implementation Plan: Recently Viewed Strip

**Branch**: `attendee/james-colebeck` | **Date**: 2026-06-16 | **Spec**: [spec.md](./spec.md)

**Jira**: [AIP-175](https://odevo.atlassian.net/browse/AIP-175) / Epic [AIP-97](https://odevo.atlassian.net/browse/AIP-97)

---

## Summary

Record each product-page visit in a session cookie (comma-separated product IDs, capped at 5). On `productHandler`, read the cookie, write the updated cookie, validate the stored IDs against the live catalogue, and pass the valid subset to a new `recently_viewed` template partial rendered below the recommendations strip. No new services, datastores, or infra changes.

---

## Phase 0: Research

### Decision log

**Cookie vs. server-side session**
- Decision: cookie
- Rationale: zero infrastructure, no new datastore, session-scoped lifetime matches "current visit" requirement in spec. The existing `currentCurrency` function already reads cookies — the pattern is established.
- Alternatives considered: in-process map keyed on session ID would require a mutex and state in `frontendServer`; rejected as unnecessary complexity.

**Strip location: product page only vs. home page too**
- Decision: product page only (below recommendations)
- Rationale: the home page already shows every product; a recently-viewed strip there is redundant. The product page is where the user lands after clicking through, and where returning to a prior item is most useful.
- Alternatives considered: home page — rejected (low value, not specified in AIP-175).

**Current product in strip**
- Decision: exclude the product currently being viewed from the strip
- Rationale: showing "you just viewed this" on the same page is confusing. AIP-175 is silent on this; consistent with standard e-commerce practice.

**Cap on strip size**
- Decision: 5 items
- Rationale: keeps the cookie small (IDs are short UUIDs) and the strip scannable. Cap applied on write (newest first, oldest evicted).

## Data Model

### Cookie: `recently_viewed`

| Field | Type | Notes |
|-------|------|-------|
| Name | string | `recently_viewed` |
| Value | string | Comma-separated product IDs, newest-first, max 5 entries |
| MaxAge | — | Not set (session cookie — expires when browser closes) |
| HttpOnly | bool | `true` (no JS access needed; strip is server-rendered) |
| SameSite | http.SameSiteLaxMode | Consistent with `cookieCurrency` |

**Example value**: `"6E92ZMYYFZ,L9ECAV7KIM,2ZYFJ3GM2N"`

### Helper functions (add to `handlers.go`)

```go
// recentlyViewedIDs reads the cookie and returns the stored IDs (may be empty).
func recentlyViewedIDs(r *http.Request) []string

// addRecentlyViewed returns a new deduplicated, capped (5) list with id prepended.
func addRecentlyViewed(existing []string, id string) []string

// filterByLiveCatalogue returns Product objects whose IDs are in ids.
func filterByLiveCatalogue(ids []string, products []*pb.Product) []*pb.Product

// excludeProduct removes the product with the given id from the slice.
func excludeProduct(products []*pb.Product, id string) []*pb.Product
```

## Quickstart

### What changes and where

#### 1. `src/frontend/main.go`

Add constant next to `cookieCurrency`:

```go
const cookieRecentlyViewed = "recently_viewed"
```

#### 2. `src/frontend/handlers.go` — `productHandler`

After the existing product fetch, before `ExecuteTemplate`:

```go
// Record this view and write the updated cookie.
existing := recentlyViewedIDs(r)
updated := addRecentlyViewed(existing, id)
http.SetCookie(w, &http.Cookie{
    Name:     cookieRecentlyViewed,
    Value:    strings.Join(updated, ","),
    HttpOnly: true,
    SameSite: http.SameSiteLaxMode,
})

// Resolve stored IDs against the live catalogue (satisfies ACs 3–5).
allProducts, _ := fe.getProducts(r.Context()) // error non-critical; nil → empty strip
recentProducts := excludeProduct(filterByLiveCatalogue(recentlyViewedIDs(r), allProducts), id)
```

Pass `"recently_viewed": recentProducts` in the `ExecuteTemplate` map.

#### 3. `src/frontend/templates/recently_viewed.html` (new file)

Follows the `recommendations.html` structure exactly:

```html
{{ define "recently_viewed" }}
{{ if .recently_viewed }}
<section class="recently-viewed">
  <div class="container">
    <div class="row">
      <div class="col-xl-10 offset-xl-1">
        <h2>Recently Viewed</h2>
        <div class="row">
          {{ range .recently_viewed }}
          <div class="col-md-3">
            <div>
              <a href="{{ $.baseUrl }}/product/{{ .Id }}">
                <img alt="" src="{{ $.baseUrl }}{{ .Picture }}">
              </a>
              <div><h5>{{ .Name }}</h5></div>
            </div>
          </div>
          {{ end }}
        </div>
      </div>
    </div>
  </div>
</section>
{{ end }}
{{ end }}
```

#### 4. `src/frontend/templates/product.html`

After the recommendations block, add:

```html
<div>
  {{ template "recently_viewed" $ }}
</div>
```

## Acceptance Criteria Traceability

| AC | Mechanism |
|----|-----------|
| AC-1: strip shown when ≥1 product viewed | cookie written on `productHandler`; template `{{ if .recently_viewed }}` gates render |
| AC-2: strip absent when no products viewed | empty/absent cookie → `recently_viewed` is nil → template conditional is false |
| AC-3: every item in catalogue | `filterByLiveCatalogue` cross-checks against live `getProducts` result on every render |
| AC-4: removed products excluded | same `filterByLiveCatalogue` call — validates at render time, not at write time |
| AC-5: strip hidden if all removed | `filterByLiveCatalogue` returns empty slice → template conditional hides strip |
